# Dashboard

Streamlit 대시보드는 **행정동별 대기 실태를 진단하고, 신규 대기거점 후보의 시뮬레이션 결과를 비교**하기 위한 화면입니다.

## 1. Purpose

대시보드는 세 가지 질문에 답하도록 구성했습니다.

1. 서울에서 대기 문제가 큰 행정동은 어디인가?
2. 선택한 행정동의 대기·취소·수요·공급 구조는 어떤가?
3. 특정 신규 대기거점 후보를 적용하면 3km 영향권의 결과가 어떻게 달라지는가?

진단 화면은 2025년 연간 데이터를 사용하고, 후보 시뮬레이션 화면은 대표 기간 **2025-08-20 ~ 2025-09-18** 결과를 사용합니다.

## 2. User Flow

```mermaid
flowchart LR
    A[서울 전체 진단] --> B[행정동 상세]
    B --> C[후보지 선택]
    C --> D[후보 시뮬레이션 결과]
```

## 3. View 1 — Seoul Overview

서울 행정동을 선택한 지표로 색칠해 전체 공간 분포를 보여줍니다.

상단에는 다음 요약값을 표시합니다.

- 서울 평균 대기시간
- 기준 이상 대기 동 수
- 지역 지니
- 지도에 표시된 동 수

지도에서 사용할 수 있는 주요 색칠 지표는 다음과 같습니다.

| 지표 | 해석 |
|---|---|
| 평균 총 대기 | 전반적인 대기 수준 |
| 60분 초과 비율 | 장기대기 위험 |
| 대기 중 포기 | 기다리다 이용을 포기한 비율 |
| 3km 내 차량 | 주변 공급 근접도 |

**이용률은 지도 색칠 지표로 사용하지 않습니다.** 낮은 이용률이 미충족 수요인지 실제 수요 부족인지 현재 데이터만으로 방향을 정할 수 없기 때문입니다. 대신 행정동 상세 화면에서는 구·서울 비교와 함께 제공합니다.

## 4. View 2 — Administrative-dong Detail

행정동을 선택하면 해당 동을 강조하고, 주요 지표와 구·서울 비교를 우측 패널에 표시합니다.

### 핵심 카드

- 총 대기 평균
- 60분 초과 비율
- 대기 중 포기
- 3km 내 차량
- 이용률

### 상세 지표

- 매칭·픽업·총 대기의 평균 / 중앙 / p90
- 취소 유형별 비율
- 시간대·평일/주말 수요
- 운행시간·거리·속도
- 등록 장애인과 이용률
- 현행 차고지 접근성

행정동 경계와 통계의 기준 시점이 달라 일부 동은 exact 매칭이 불가능합니다. 이 경우 근사 매칭 여부나 데이터 결측 사유를 화면에 표시합니다.

## 5. View 3 — Candidate Simulation

후보 한 곳을 선택하면 해당 후보의 3km 영향권과 시뮬레이션 결과를 보여줍니다.

### 주요 결과

| 지표 | 의미 |
|---|---|
| 픽업 개선율 | 기존 픽업시간 대비 변화율 |
| 평가 구간 | Seed 3회에 따른 변동 범위 |
| 총 절감량 | 영향권 전체에 누적되는 픽업시간 감소량 |
| 영향권 콜 수 | 결과가 적용되는 수요 규모 |
| 영향권 동 수 | 3km 범위에 포함된 행정동 수 |
| `n_overlap` | 해당 평가 구간과 겹치는 다른 후보 수 |

후보 목록은 **개선율**과 **총 절감량** 두 기준으로 정렬할 수 있습니다. 두 지표는 각각 지역의 평균 개선 정도와 전체 수혜 규모를 보여줍니다.

### Scenario premise

모든 후보는 같은 개입 조건을 사용합니다.

- 신규 거점 배속 정원 +10대
- 기존 44개 거점 배속 유지
- 평일 가동 차량 574 → 582대
- 주말 가동 차량 374 → 379대

이 조건을 결과 근처에 함께 표시해 후보 효과의 전제를 확인할 수 있도록 했습니다.

### Influence-area map

후보지 기준 3km 영향권을 지도에 표시합니다. 평가 결과는 영향권 전체를 콜 수로 가중한 값 하나이므로, 영향권 내부 동을 서로 다른 농도로 칠하지 않습니다. 동별 after 효과가 없는 상태에서 서로 다른 색을 사용하면 존재하지 않는 공간 차이를 표현하게 되기 때문입니다.

## 6. Uncertainty Display

후보 효과는 Seed 42·43·44의 반복실험을 기반으로 표시합니다.

- 개선율과 함께 반복실험 평가 구간 제공
- 후보별 `n_overlap` 제공
- 3km 콜 2,000건 미만일 때 표본 부족 표시
- 시드별 원값은 상세 패널에서 확인 가능

총 대기시간은 모델에서 절대 수준이 충분히 재현되지 않으므로, 실측과 시뮬레이션 before를 함께 확인할 수 있도록 보조 정보로 제공합니다.

## 7. Boundary & Data Integrity

행정동 경계 파일과 콜 원본의 행정동 구분이 완전히 일치하지 않습니다.

- exact / manual / approx 순서로 경계를 연결합니다.
- 여러 지표 행이 한 폴리곤으로 합쳐질 때는 승차 완료 건수로 가중합니다.
- 대응 지표가 없는 경계는 데이터가 없는 것으로 별도 표시합니다.
- 신뢰 기준 미달 동은 값을 숨기지 않고 표본 수 경고를 함께 표시합니다.

지도는 데이터가 없는 지역과 값이 좋은 지역을 시각적으로 혼동하지 않도록 구성했습니다.

## 8. Implementation

| 항목 | 기술 |
|---|---|
| Framework | Streamlit |
| Map / Chart | Plotly |
| Spatial data | GeoPandas / GeoJSON |
| State | `st.session_state` |
| Performance | `st.cache_data`, 단순화된 표시용 경계 |
| Candidate result | `placement_grades.csv`, `placement_eval.csv` |

대시보드는 원본 콜 데이터를 직접 읽지 않고 공개 가능한 파생 산출물을 사용합니다.
