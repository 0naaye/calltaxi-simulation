# Data Processing & Validation

이 문서는 **분석 입력을 어떻게 정리했고, 어떤 기준으로 데이터와 시뮬레이션을 검증했는지** 설명합니다.

## 1. Dataset Scope

콜 원본은 2025년 특장차 운행 데이터 **1,390,969건**입니다.

| 단계 | 건수 |
|---|---:|
| 특장차 원본 | 1,390,969 |
| 즉시콜 + 서울 출발 필터 후 | **1,222,330** |
| 승차 완료 | 1,033,135 |

주요 필터는 다음과 같습니다.

- **즉시콜**: 예정시각과 접수시각 차이가 2분 이내
- **서울 출발**: 출발 자치구가 서울 25개 구
- **특장차 한정**: 임차택시와 다른 운영 패턴을 분리

## 2. Data Quality Checks

### 승차거리 0

완료 운행 중에도 승차거리가 0으로 기록된 사례가 있습니다. 운행시간과 요금은 정상인데 거리만 없는 결측 대체값으로 판단해, 거리·속도를 사용하는 분석에서는 제외했습니다.

- 원본 완료 운행 중 거리 0: 4,636건
- 필터 후 거리 0 완료 운행: 4,183건
- 정상 완료 운행의 승차거리 중앙: 약 5.58km

### 정산 미기록

승차·취소 기록 없이 하차만 있는 운행은 실제 운행이 이루어진 것으로 보여 취소로 분류하지 않았습니다.

- 원본: 616건
- 필터 후: 524건

이 건을 취소에 포함하면 취소율이 15.44%에서 15.48%로 증가하므로 별도 상태로 분리했습니다.

### 연간 고유 차량과 실제 공급 구분

연간 등장한 고유 차량번호 723대는 특정 시점의 운행 차량 수가 아닙니다.

| 구분 | 차량 수 |
|---|---:|
| 연간 고유 차량번호 | 723 |
| 연간 일별 중앙 | 561 |
| 평일 일별 중앙 | **574** |
| 주말 일별 중앙 | **374** |

723대를 그대로 사용하면 공급을 약 29% 과대하게 반영하게 됩니다. 시뮬레이션은 평일·주말 실제 가동 규모를 따로 사용합니다.

## 3. Administrative-dong Matching

콜 데이터와 행정동 경계의 표기가 달라 단순 문자열 조인으로는 대량의 불일치가 발생했습니다. 표준화 후 3단계로 매칭했습니다.

| 단계 | 방식 | 건수 |
|---|---|---:|
| exact | 숫자 앞 `제`, 공백, 구두점 등을 정규화한 직접 일치 | **1,179,688** |
| approx | 분동·합동의 기본명 그룹을 이용한 근사 매칭 | **34,505** |
| manual | 행정구역 개편·개명 사례의 수동 매핑 | **8,137** |

경계 파일과 콜 데이터가 서로 다른 행정구역 시점을 사용하기 때문에, 일부 불일치는 전처리만으로 완전히 제거할 수 없습니다.

## 4. Travel-time Validation

승차→하차 완료 운행을 이용해 이동시간 테이블을 만들었습니다.

| 방식 | 커버율 | 실측 대비 절대중앙오차 |
|---|---:|---:|
| 실측 OD | **76.5%** | 2.1분 |
| 거리·속도 모델 | **23.1%** | 4.9분 |
| 전체 | — | **약 2.5분** |

실측 기반 이동시간의 중앙은 약 19.9분, 승차거리 중앙은 5.12km, 속도 중앙은 15.7km/h입니다. 전체 조회 결과는 1~120분 범위로 제한하고, 전 동쌍 조회에서 결측·0·음수 값을 확인하지 않았습니다.

## 6. Cancellation & Patience Validation

취소를 한 종류로 보지 않고 발생 시점에 따라 분해했습니다.

| 구분 | 건수 | 전체 콜 대비 |
|---|---:|---:|
| 즉시 취소 | 38,578 | 3.16% |
| 대기 중 포기 | **104,422** | **8.54%** |
| 배차 후 취소 | 45,671 | 3.74% |
| 합계 | 188,671 | 15.44% |

대기 중 포기는 Kaplan–Meier 생존곡선으로 모델링했습니다. 취소자만 사용하면 중앙 인내심이 16.8분으로 추정되지만, 승차한 콜을 우측절단으로 포함하면 **186분**으로 크게 달라집니다.

## 7. Simulation Validation

후보 평가에 사용한 대표 기간의 실측값과 현행 배치 시뮬레이션을 비교했습니다.

| 지표 | 실측 | 시뮬레이션 | 해석 |
|---|---:|---:|---|
| 픽업 평균 | 18.80분 | 12.08분 | 절대 수준 미달 |
| 픽업 중앙 | 17.76분 | 9.45분 | 절대 수준 미달 |
| 픽업 지니 | **0.0751** | **0.0805** | 공간 격차 구조는 비교적 근접 |

총 대기시간도 실측보다 짧게 재현됩니다. 가장 큰 원인은 실제 시스템의 매칭 지연과 차량 선택 과정이 원본 데이터에서 충분히 관측되지 않아 단순화되어 있기 때문입니다.

따라서 모델은 **절대 대기시간 예측 모델이 아니라 후보 간 상대 비교를 위한 시뮬레이션**으로 범위를 제한합니다.

## 8. Candidate Data Validation

후보 풀은 639곳이며, 특장차 진입 가능성을 확인하기 어려운 옥내·혼합 시설을 제외해 옥외 348곳을 사용했습니다.

| 단계 | 후보 수 |
|---|---:|
| 전체 후보 풀 | 639 |
| 옥외 후보 | 348 |
| 행정동 배정에 사용된 서로 다른 후보 | **244** |
| 후보가 배정된 행정동 | 383 / 426 |

미배정 동은 분석에서 삭제하지 않고 진단 화면에는 유지합니다. 후보 풀이 제한되어 시뮬레이션 대상에서만 제외됩니다.

## 9. Known Data Limitations

- 취소 건에는 차량번호가 없어 해당 차량의 실제 운행 시퀀스를 완전히 복원할 수 없습니다.
- 콜·경계·등록 장애인 통계의 행정동 기준 시점이 서로 다릅니다.
- 일부 서울 밖 목적지는 행정동 중심 좌표를 확보하지 못해 이동시간 폴백을 사용합니다.
- 차량의 유휴 위치와 기사 휴게·충전 상태는 직접 관측할 수 없습니다.
- 옥내·혼합 주차장의 특장차 진입 유효고를 확인할 일관된 공개 데이터가 없습니다.
- 원본 콜 데이터는 개인정보 및 이용 조건 때문에 공개 저장소에 포함하지 않습니다.
